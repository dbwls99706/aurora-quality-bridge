# Aurora Quality Bridge

품질 이슈 접수부터 배치 판단, 검토 의결, 부서 회신과 공급 복구까지 연결하는 업무 시뮬레이션입니다. 삼일PwC AX 인재전쟁의 W03 시나리오를 바탕으로 만들었습니다.

## 주요 기능

- 원본 자료와 계산 근거를 함께 확인하는 사건별 업무 화면
- 출하 배치와 품질 이슈의 연결, 승인 권한 및 검토 이력 관리
- 전량·분할 공급안 비교와 영업·생산 부서의 모의 회신
- AI 검토 초안과 사람의 검토·의결을 분리한 처리 흐름
- 공개 데모의 방문자별 데이터 분리, 만료 후 새 연습 시작
- 서버측 AI 키 관리, 호출 전 예산 예약과 사용량 제한

실제 고객 연락, 회수, 발주 또는 조직의 의결을 실행하지 않습니다. 데이터룸의 기업과 거래 내역은 대회용 가상 자료입니다.

## 로컬 실행

Python 3.10 이상에서 실행합니다.

```sh
python backend.py --host 127.0.0.1 --port 8000
```

소개 화면은 `http://127.0.0.1:8000`, 업무 화면은 `/workspace`입니다. 로컬 역할 선택은 모의 역할 전환입니다. 로컬 서버를 인증 없이 인터넷에 노출하지 마세요.

## 테스트

```sh
python -m unittest discover -s tests
python -m unittest discover -p 'test_public*.py'
npm ci
npm test
```

프런트엔드 테스트는 Node.js 22.12 이상이 필요합니다. 실제 PostgreSQL과 외부 AI 호출은 별도 환경에서 검증해야 하며, 로컬 테스트 결과만으로 해당 통합이 검증되는 것은 아닙니다.

## 배포 설정

`Dockerfile`과 `axhub.yaml`은 PostgreSQL을 사용하는 공개 데모용 구성입니다. 로컬 SQLite 실행과 별개의 진입점인 `public_demo_cloud.py`를 사용합니다.

이 저장소의 앱·DB·소유자 식별자는 예시 값이며 공개 및 AI 활성화 설정은 꺼져 있습니다. 배포 시 `public_demo_cloud_profile.py`와 `public_demo_postgres.py`의 명시적 연결 허용 목록을 새 환경에 맞게 설정하고, 소유자 검증과 방문자 격리 시험을 먼저 수행해야 합니다. 예시 설정을 실제 운영 설정으로 그대로 사용하지 마세요.

API 키는 서버의 Secret/Runtime 환경변수로만 설정합니다. 키, 세션, 운영 DB, 사용 장부와 인증 파일은 저장소에 넣지 않습니다. AI 예산은 호출 전에 예약되며 실패·시간 초과 시에도 예약을 유지합니다. 앱 접속 만료는 호스팅 과금 중단과 다릅니다.

## 구성

- `backend.py`, `persistence.py`: 업무 규칙, API와 저장 처리
- `public_demo*.py`: 방문자 분리와 공개 데모 경계
- `public_ai.py`, `ai_budget.py`: AI 어댑터와 사용 한도
- `static/`: 소개 및 업무 화면
- `data/original/`: 대회에서 제공한 가상 데이터룸
- `tests/`, `test_public*.py`: 회귀 테스트

대회 제공 데이터와 제3자 구성요소의 권리는 각 권리자에게 있습니다. 이 저장소는 해당 자료에 대한 별도의 재배포 허락이나 라이선스를 부여하지 않습니다.
